# 从作者操作角度使用 ALCC 研究流程

2026-09-30。用户已接受约 1–2 个月实质重构，无需再次确认这个窗口。

## 你的职责与当前状态

你负责确定研究价值、现实假设、导师要求和可投入资源。主 agent 负责把这些条件变成文献审计、推导、代码、实验及有证据的建议。你不需要每天设计提示词、手动编辑 JSON 或逐个批准常规检查。

目前工作区已建立，但 R001 未执行／冻结，没有训练或外部定时任务在运行，也没有一条现成的“启动全部研究”命令。持续研究需要实际会话或另行落地的调度；一段启动提示词本身不提供未来数周的无人值守运行。

## 现在提供什么

不需要重复上传现有稿件 PDF、审稿意见或参考 ZIP。不知道的信息可以写“不确定”；可从本地查到的版本、硬件型号和程序入口由 agent 自行检查。

| 信息 | 你提供什么 | 对决策的作用 |
|---|---|---|
| 成果优先级 | 建议：窗口内形成可投稿版本 > 实质理论／算法提升 > 更高投稿层级；说明是否同意 | 第一周失败后是收缩还是继续冒险 |
| 导师硬要求 | RL／MAPPO 是否必须保留，WSN 是否必须为主应用，“拔高”更重数学新意还是跨应用算法 | 避免围绕导师不会接受的方向重构 |
| 资源可用性 | 哪台机器可用、共享情况、可用时段、不能干扰的作业、可接受占用时间 | 设备型号不等于可占用的资源 |
| 成本边界 | 本地训练时间边界；是否考虑额外付费计算／模型调用，未决定可暂不纳入 | 不照抄来源项目四小时预算 |
| 材料权威性 | 哪份源码、稿件和结果有效；有无已知作废版本；可编辑稿件位置若已知可指出 | 不围绕旧错误组织新研究 |
| 领域事实 | 优先级怎样变化、容量是否变化、能否集中协调、切换主要花什么成本 | 判断理论条件是否有应用意义 |

如有毕业、答辩等不可移动日期，提供实际日期；否则沿用现有时间窗口。缺少资源信息时仍可先做文献、推导、代码审计与实验设计。

## 第一轮怎样开始

可在当前对话提供上述信息，并使用下面的启动文本：

> 按 autoresearch/rounds/R001/PLAN.md 开始研究路线筛选。先做最接近文献、独立推导／反例和原代码口径审计。把证书复用当作可被否定的候选。继续准备最小原型；比较实验开始前明确成本、协议和判定标准。阶段结束给出继续／缩小／停止的建议及证据。缺失信息不影响的工作先推进。

不需要先安装参考项目或复现其 1152 条训练轨迹。第一轮可以先用精确小实例、固定或枚举候选，无需先训练 MAPPO。

## 第一次回报应该包含什么

| 交付 | 你应该看什么 | 不合格的交付 |
|---|---|---|
| 最近理论对照 | 哪个假设、结论或算法步骤超出现有工作？ | 只有论文摘要，最后声称有创新 |
| 理论审计 | 保证是什么、适用条件是什么、反例是什么？ | 只有新增定理编号和复杂公式 |
| 原型结果 | 完整计账后是否有希望降低成本？强基线是否公平？ | 只统计优化迭代，漏算检查和执行成本 |
| 研究决定 | 下一阶段增加什么信息，成本与退出条件是什么？ | 只说建议继续深入研究 |

不需要你重算每个实验，但作者应能解释核心保证、现实假设及与最近工作的差异。模型或 reviewer 的“通过”不能替代可逐步检查的证明；agent 应提供推导供你与导师审阅。

## 你和导师需要判断的四件事

### 1. 方向是否值得继续

第一周结束应允许三种结果：继续；缩小为特定场景算法；停止该主线并修正现稿。停止候选主线不等于放弃整篇论文。

建议不要把复杂定理本身当作收益。判断增量是否解决了值得解决的问题、是否足以支持你希望的论文类型。agent 应提供证据和推荐，而不是让你在没有信息时选择路线。

### 2. 理论条件是否符合实际

当前候选特别需要你判断：容量阶段内固定是否合理；协调器或原子联合提交是否可行；稀疏优先级变化和较高缓存复用是否常见；学习器只负责提案、理论不证明 MAPPO 收敛，是否符合导师期待。

这些领域事实不能靠更好看的实验代替。如果条件不合理，应修改模型或收缩范围，不应只为证明方便改变假设后继续保留广泛声明。

### 3. 什么改善值得完整实验

先确定主要目标是降低计算、减少切换还是提高网络效用。由 agent 根据应用要求和短校准提出指标、效果门槛、可接受代价与对照，再在方法比较结果出现前固定。

若核心贡献是计算节约，应在可比较的决策质量下计量总成本；若允许效用损失，应预先明确程度或报告完整质量—成本曲线。不要要求所有指标都胜出，也不要看完结果才选最有利指标。来源项目的 0.3 个百分点与 ALCC 无关。

### 4. 何时停止扩展，完成论文

第二应用、新定理和更多学习模块都占用时间。判断它是否改变核心结论、是否是当前标题必须的证据，以及是否挤掉确认与写作阶段。建议第六周若主线仍摇摆，优先收缩到有证据的版本，保留明确的稿件完成阶段。

## 每阶段具体做什么

| 阶段 | agent 负责 | 你主要做什么 |
|---|---|---|
| 第 1 周路线筛选 | 文献、证明、反例、代码审计、低成本原型设计与可行试验 | 与导师判断价值和现实假设；决定继续／缩小／停止 |
| 第 2–4 周开发 | 实现、强基线、公平预算、校准与开发实验 | 给出资源边界和效用／成本取舍；无需逐个批准种子 |
| 第 5–6 周确认 | 封存候选、未参与选型的场景评价、统计与失败分析 | 若结论改变，选择收缩声明或另立问题 |
| 第 7–8 周收束 | 论文、图表、理论—实现一致性和审稿式检查 | 审阅核心解释、作者责任与投稿取舍 |

这是规划，实际进度按证据调整，不是后台连续运行承诺。窗口只有六周时，可减少非必要扩展并并行写作，不能省略公平对照与确认。

设备和精确耗时未知时，由 agent 检查、校准并形成执行方案；你给资源可用性和可接受投入，不需要猜每个 trial 的时长。已有范围内工作无需重复确认；付费或明显扩大范围的计划需具体化后再沟通。

## 怎样监督而不被日志淹没

每阶段只要求六项：本轮问题与答案；最强证据和最危险反例；偏离、失败与未完成项；累计成本和真实运行状态；现在允许写进论文的一句话；下一动作、推荐理由和是否需要你判断。

沟通以阶段完成、重要发现、失败、预算变化为节点，正常训练无需持续追问。暂停时明确说明，恢复时核对状态与剩余预算。未来如要无人值守，应实际配置并验证唤醒、日志、停止与恢复机制；当前尚未建立。
