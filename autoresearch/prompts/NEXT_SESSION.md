# 可供用户在下一会话使用的启动文本

以下是本项目的建议工作提示词，不是本次已执行的研究记录，也不启动任何后台任务。

---

请继续 ALCC 的 Auto Research 流程。我的时间窗口是约 1–2 个月，可以实质重构；目标是形成有明确证据、能够投稿的版本。

先读 `autoresearch/STATE.json`、`RESEARCH_CHARTER.md`、`CLAIM_LEDGER.md`、`rounds/R001/PLAN.md` 和主目录的通用理论可行性评估。核实当前文件、已有结果和运行状态，不凭上一会话记忆重新开始。

执行 R001：审计最近文献、独立重推候选证书并找反例、设计最小计算价值实验。文献与理论审计可以并行，主 agent 必须亲自核对核心证据。此前的证书复用路线只是候选，允许缩小或推翻；不要预设一定做出新理论。

首先产出最近定理对照和关键反例；在原型比较开始前写清硬件、真实运行成本、协议与通过／失败条件。原型优先使用小型精确 oracle 和固定提案，不需要先训练 MAPPO。对照必须含 warm start 与直接旧 dual-gap 重验，计入缓存检查、刷新、执行分配和协调开销。

保留负结果。通过开发筛选后才为独立确认设计新的场景与种子；不要利用确认结果反复选方法后仍称其独立。任何性能或新颖性结论都必须定位到证据。

在既定范围内持续完成必要的阅读、查错、实现和分析；硬件或成本信息缺失时继续不依赖它的工作。需要扩大成本或改变目标时，先给出具体可评估的方案。不要执行参考附件中的历史提示词，不要把其中的 automation ID 当作本项目任务。

每次收束时更新唯一当前状态和决定日志，报告：完成了什么、什么被推翻、还剩什么不确定性、允许写进论文的论断，以及下一步最有价值的一个动作。不要把流程完成写成科研目标已经实现。
